# Structured data for AI citation

The AEO scorer recommends emitting JSON-LD for **6 active schema
types** that AI engines use to ground entities. Generated by
`scripts/aeo/schema_generate.py` and embedded in the publish payload
when the integration supports it (Dev.to does; LinkedIn UGC does not).

## Which types to emit

| Type             | When                                          | Why                                                          |
|-------------------|-----------------------------------------------|---------------------------------------------------------------|
| `Article`         | Every blog / substack post                    | Maps the post to the AI engine's article index                |
| `Organization`    | Once, in the publishing identity              | Grounds the brand entity                                       |
| `Person`          | Every author byline                           | Grounds the author entity; satisfies Google "Who" test         |
| `WebPage`         | Wrapper on the article page                   | Maps the page itself; provides URL canonicalization            |
| `BreadcrumbList`  | When the post belongs to a category hierarchy | Provides parent-context for AI engine summarization            |
| `ImageObject`     | Hero image only                                | Carries author + caption attribution                           |

## Types we DO NOT emit (with rationale)

| Type             | Why we skip                                                       |
|-------------------|-------------------------------------------------------------------|
| `FAQPage`         | Rich result removed for non-government/healthcare sites (Aug 2023). |
| `HowTo`           | Rich result removed Sept 2023.                                     |
| `Product`         | Out of scope — we publish marketing content, not products.         |
| `Dataset`         | Retired from rich results late 2025.                               |
| `ClaimReview`     | Retired from rich results June 2025.                               |

Emitting deprecated types doesn't hurt, but it bloats the JSON-LD
without lifting AI citation.

## Article template

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "...",
  "datePublished": "2026-05-28",
  "dateModified": "2026-05-28",
  "author": {
    "@type": "Person",
    "name": "...",
    "url": "...",
    "sameAs": ["https://www.linkedin.com/in/...", "..."]
  },
  "publisher": {
    "@type": "Organization",
    "name": "...",
    "logo": {"@type": "ImageObject", "url": "..."}
  },
  "mainEntityOfPage": {
    "@type": "WebPage",
    "@id": "<canonical url>"
  },
  "image": {
    "@type": "ImageObject",
    "url": "...",
    "caption": "..."
  }
}
```

## How the scorer uses this

The `entity_grounding` sub-signal (weight 15%) reads:

- **1.0** if both `Article.author.sameAs` and `Article.publisher` are
  present and non-empty.
- **0.5** if one is present.
- **0.0** if neither.

The check is performed against the JSON-LD that would be emitted —
the script doesn't require the schema to be in the body yet. The
final schema is injected at publish time.

## How the reviser uses this

When `entity_grounding < 0.5`, the reviser MAY apply rewrite kind
`ground_entity` — replacing the first mention of "we" or "our team"
with a named person + role ("Author at OrgName" or similar). The
reviser does **not** generate the JSON-LD itself — that's
`schema_generate.py`'s job at publish time. The reviser's job is
ensuring the **body text** mentions the entities that the JSON-LD
will reference, so the body and the structured data agree.

## Note on JavaScript-rendered JSON-LD

Per Google's December 2025 JS SEO guidance, structured data injected
via JavaScript may face delayed processing. For our publishing
surfaces:

- **Dev.to:** server-renders JSON-LD; no JS dependency.
- **LinkedIn UGC:** doesn't accept arbitrary JSON-LD; entity
  grounding happens through `Person URN` + LinkedIn's own author
  surface. The body's entity references are what AI engines see.
- **Substack:** server-renders; JSON-LD goes in the `<head>`.

Always include JSON-LD in the **server-rendered** HTML at publish
time, not via a runtime script tag. The `schema_generate.py` script
emits a string the publishing integration includes in its POST body.
